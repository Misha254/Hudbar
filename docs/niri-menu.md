# Меню HUDbar в niri

Меню — слой `zwlr_layer_shell` в слое `Overlay` без якорей, поэтому
композитор центрирует его сам. Клавиатура `Exclusive`: первое нажатие после
бинда доходит до меню, а потеря фокуса закрывает его.

Ничего из этого документа применять не нужно автоматически: файл объясняет,
что и куда вписать руками.

## 1. Размытие под меню

Слой называет себя `hudmenu`. Правило для `~/.config/niri/rules.kdl`:

```kdl
layer-rule {
    match namespace="^hudmenu$"
    background-effect { blur true saturation 0.9 xray false }
}
```

Фон карточки получает прозрачность `CARD_ALPHA` (0.94) — сквозь него видно,
что именно размывается. Затемнения вокруг карточки нет: под меню должны быть
видны терминал и обои.

Если правило не сработает, меню останется читаемым, просто без размытия.

## 2. Бинды

Текущий вариант — нампад, рядом с остальными биндами HUDbar:

```kdl
KP_4 repeat=false hotkey-overlay-title="Меню HUD" { spawn-sh "~/.local/bin/hud-menu"; }
```

Если `KP_4` занят чем-то нужным, вариант на `Super`:

```kdl
super+alt+Space repeat=false hotkey-overlay-title="Меню HUD" { spawn-sh "~/.local/bin/hud-menu"; }
```

`repeat=false` обязателен: удержание клавиши не должно открывать меню пачками.

Раздел «Питание» открывается своим биндом — он заменяет прежнее меню питания
на rofi:

```kdl
super+P repeat=false hotkey-overlay-title="Питание" { spawn-sh "~/.local/bin/hud-menu power"; }
```

## 3. Прямой вход в раздел

Обёртка передаёт аргументы бинарнику, поэтому раздел можно открыть сразу:

```sh
hud-menu style          # сразу «Стиль»
hud-menu notifications  # сразу «Уведомления»
```

Разделы: `apps`, `panel`, `style`, `notifications`, `capture`, `keybinds`,
`system`, `power`, `about`. Неизвестное имя открывает корень, без ошибки.

При прямом входе `Esc` с открытого раздела закрывает меню, а не возвращает
на корень: возвращаться туда, где пользователь не был, незачем.

## 4. Установка

```sh
cargo build --release --bin hud-menu-rs
install -m 0755 target/release/hud-menu-rs ~/.local/bin/
install -m 0755 scripts/hud-menu ~/.local/bin/
```

Затем один раз:

```sh
niri msg action load-config-file ~/.config/niri/config.kdl
```

Если `install.sh` уже обновлён, всё это делает он: `install.sh` кладёт и
`hud-menu-rs`, и `hud-menu`.

## 5. Что происходит при повторном вызове

Меню держит pid-файл `$XDG_RUNTIME_DIR/hudbar-menu.pid`. Слой не виден в
`niri msg windows`, поэтому pid-файл — единственный способ узнать, открыто ли
меню:

- файл есть, процесс жив → новый запуск посылает старому `SIGTERM` и выходит;
- файл есть, процесса нет (убит или перезагрузка) → файл перезаписывается;
- файла нет → пишется свой pid.

Файл снимается при любом выходе, включая `SIGTERM`, так что повторные
нажатия не оставляют зомби-процессов и не блокируют следующий запуск.

Сбросить вручную, если что-то залипло:

```sh
rm -f "$XDG_RUNTIME_DIR/hudbar-menu.pid"
```

## 6. Чек-лист ручной проверки

- [ ] `hud-menu` открывает меню поверх панели, рабочие области не меняются.
- [ ] первое нажатие (стрелка) сразу двигает выделение, без «попадания» в терминал.
- [ ] печать по-русски и по-английски фильтрует список, кириллица находится по латинице.
- [ ] `Esc` на корне закрывает; на разделе возвращает на корень; при непустом запросе сначала чистит запрос.
- [ ] `hud-menu style` открывает сразу «Стиль», и `Esc` оттуда закрывает, а не возвращает на корень.
- [ ] повторный вызов бинда закрывает меню, а не открывает второе.
- [ ] клик мышью по строке выбирает и открывает; колесо листает список.
- [ ] переключение на другое окно закрывает меню (потеря клавиатуры).
- [ ] обе темы: normal и pixel, включая `hud-theme pixel`.
- [ ] масштаб 1 и 2: подписи не мылятся, меню по центру.
- [ ] спам бинда 10 раз подряд: остаётся один процесс, в `$XDG_RUNTIME_DIR` нет `.tmp`.
