# ROADMAP

## Статус

W5.1 (звук), W5.2a/b (Wi-Fi), W5.3a/b (Bluetooth), W5.4a/b/c (дисплеи),
W5.5 (хранилища), W5.6 (OSD громкости) — готовы, проверки зелёные.

## A. W5.3b — Bluetooth-действия

- Устройство: `connect`, `disconnect`, `trust on/off`, `untrust`, `pair`, `unpair`
  (`untrust` + `remove`), один `info` на **выбранное** устройство (trusted, RSSI,
  батарея, UUID) — не на каждое, иначе N+1.
- Адаптер: `power on/off`.
- Сканирование: `scan on` с гарантированным `scan off` — по таймауту и при
  выходе из раздела.
- Парная зона: без агента `pair` может не пройти. Вариант —
  `bluetoothctl --agent NoInputNoOutput pair <MAC>`, проверить на живом устройстве.
- Строки устройств становятся кнопками; тот же вид строки с состоянием, что в
  Wi-Fi (busy/ошибка/готово), `CommandJob.row`, подтверждение на `unpair`.
- Всё через `CommandSpec` + `with_timeout`, без shell. Тесты валидируют argv.
- Готово, когда: подключение/отключение устройства и `power` работают у живого
  адаптера, курсор после refresh на месте, тесты на каждое действие.

## B. W5.4a — дисплеи, только чтение

- Источник: `niri msg --json outputs` — `name`, `make`/`model`, `current_mode`,
  `modes` (с `is_preferred`), `vrr_enabled`/`vrr_supported`, `transform`, `scale`,
  `position`, `dpms_status`, `mirroring`.
- Модель `OutputSnapshot`, строки: имя + режим, разрешение, масштаб, положение,
  VRR, вкл/выкл. Без команд записи.
- Сверить точный JSON на ноутбуке: у гибрида Intel/NVIDIA набор полей может
  отличаться.
- Готово, когда: список совпадает с включёнными выводами niri и переживает
  переподключение кабеля.

## C. W5.4b — управление дисплеями

- Сначала `niri msg output --help`: точная грамматика `mode`, `--scale`,
  `--transform`, `--position`, вкл/выкл, `power-off-monitors` / `power-on-monitors`.
- Действия: режим, масштаб, трансформ, положение, вкл/выкл, пресеты раскладки.
- Развилка до кода: msg-команды временны, либо пишем изменения в
  `~/.config/niri/config.kdl` (с бэкапом). По умолчанию — временные правки,
  запись в конфиг только явно.
- VRR и зеркалирование — только в конфиге; вынести в «продвинутое» или не делать.
- Готово, когда: сценарий «внешний монитор» настраивается из меню.

## D. Zen Browser через matugen

- Шаг 0 — разведка, без кода: профиль flatpak
  (`~/.var/app/app.zen_browser.zen_browser/`), наличие `chrome/`, `mods/`,
  где именно Zen грузит кастомный CSS (`chrome/userChrome.css` / корень профиля /
  только Zen Mods). От этого зависит вся реализация.
- Шаблон matugen (`~/.config/matugen/templates/zen.ftl`) + запись в конфиг
  генерации, чтобы тема обновлялась вместе с wallpaper.
- Ограничения: `userChrome.css` требует перезапуска браузера; тёмная/светлая
  через `prefers-color-scheme`; стилизовать только Zen-специфичные элементы.
- Готово, когда: тема работает в обоих режимах и переживает смену обоев.

## F. Доводка

- OSD: сделано (W5.6) — своё окно на layer-shell вместо уведомления dunst.
  Ключевое решение: события звука приходят из `pactl subscribe`, а не из
  секундного опроса состояния, иначе окно появлялось бы на секунду позже
  нажатия. Время показа и включение — в секции `osd` файла `settings.json`
  и в Control Center. Не покрыто: яркость (её меняет не панель) и OSD
  микрофона по внешнему mute.
- Уведомления opencode: плагин opencode на `session.idle` и ожидание прав
  дёргает `notify-send`/HUDbar.
- Secret hardening (будущее, не W5.x): пароль Wi-Fi сейчас идёт через
  `CmdArg::Secret` в `argv` и виден через `ps`; `CmdArg`/`CommandSpec`
  клонируемы вместе с `Action`. Перевод на stdin/keyring и ограничение
  клонирования секрета — отдельной задачей, не раньше закрытия W5.
- Крышка: сначала разведка поведения. `logind HandleLidSwitch` + `swayidle` +
  `niri msg action power-off-monitors` могут конфликтовать. Закрыл — suspend,
  открыл — восстановление, внешний монитор жив.
- Мелочи: анимации, курсор после обновления, звук, шрифты.

## G. Система как законченная ОС

- Обновления + снапшоты btrfs: snapper, timeline, pre/post-хуки на pacman,
  flatpak, fwupd; документированный откат. Снапшотить и `/`, и `/home`.
- PKGBUILD: hudbar, hud-menu-rs, hud-wallpaper-rs + конфиги.
- Мастер первого запуска: имя хоста, часовой пояс, локаль, раскладка, GPU,
  Wi-Fi, первый снапшот.
- Полный английский: всё через i18n — ошибки провайдеров, динамические
  заголовки, единицы, формат даты/времени.
